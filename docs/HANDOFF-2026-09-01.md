# Handoff: Codex fleet stop, 2026-09-01

The Codex agent fleet ran out of usage on 2026-09-01 with a large body of work
uncommitted. This file records what was landed, what was left open, and where
the unlanded material lives so the work can be finished.

## What landed

Commit `a8d9d7a6` on `slipgate` preserves the entire uncommitted working tree:
530 files, 148 added, 186 deleted, 196 modified. It builds clean under
`make -f GNUmakefile` and produces `gamex86_64-lmctf-r1925~0017ab60.so`.

It is one commit rather than several because the change set interlocks: the
toolchain retirement, the compact-model migration, and the build changes all
touch `GNUmakefile` and `Makefile`. Splitting further would produce
intermediate commits that do not build.

Two `clang --analyze` outputs were deliberately left uncommitted and are not

### Python toolchain retirement

`PROJECT-COMPLETION-PLAN.md` gained the rule that the repository contains no
Python source, tests, build hooks, runtime, or documentation. The commit
implements it: the Python corpus controller, finalizer, bundle, fleet,
analysis, and test programs are gone, along with the duplicate
`runeaccept.c`, `runev2read.c`, and `runev2makecheck.c` parsers.

`tools/runecompactread.c` survives as the single canonical C wire inspector.
`tests/run_c_build_ownership_test.sh` is new and asserts the retired sources
stay deleted and stay out of every build manifest. CI no longer builds a
Python venv or installs `tools/requirements.txt`, and now refuses to package
the offline `-rune-generator.so` as the runtime module.

### Compact model migration

`sg_rune_late_path`, `sg_rune_learning`, and the v2 artifact publication and
semantic units were replaced by `sg_rune_compact_*` equivalents, adding the
compact composer, generation, mechanisms, movement fields, pmove control,
portal snapshot, field service and region hierarchy, response partition,
static materializer, and weapon catalog units with focused tests.

### Documentation

`DEPENDENCY-GRAPH.md` records the offline generator module split: `sv rune`
connects to the compact field builder in an unshipped generator module, while
shipped modules keep only the compact loader/runtime and fail closed on
generation. Three plan checkboxes moved to complete: hook and weapon
visibility partitioning at first-hit and silhouette discontinuities,
static-field caching with a coarse region hierarchy, and probabilistic
weapon-effect integration with exact live pre-fire validation.

## Resolved: the ground capability publication failure

`a8d9d7a6` left `ground-capability-publication-test` failing. It is fixed in
`d15c43bb`, and `make -f GNUmakefile -k host-test` now completes with no
failing target.

The visible cause was `SG_RUNE_MODEL_MAX_CELL_PHASES`, a fixed ceiling of 32
phases per cell that rejected the finer partition the new exact spatial index
produces. Removing it exposed the real defect: `sg_ground_phase_binding_t` was
`{cell, phase}`, so pose localization searched every phase bound to a cell and
matched on basis attributes alone. Because the phase catalog emits one phase
per semantic region, two regions of a cell sharing a basis made every pose in
that cell ambiguous. The ceiling had been masking it.

Bindings now carry their region, ordered by `(cell, region, phase)`. Lookup
bisects to a region and scans only that region's bindings. See `d15c43bb` for
the call sites and the reconstruction remap this required.

Every arbitrary per-cell ceiling was removed in the same commit. Each sat
beside a `SpanWithin` check that already bounds the span, so they added nothing
to hostile-input validation and only rejected geometry the host accepts.

## Design work that produced no code

Several 2026-09-01 sessions were read-only evaluation agents that were still in
their grounding phase when usage ran out, so they left no diff. Two produced
conclusions worth keeping:

- On representing the host collision evaluator: rejected compiling the whole
  evaluator into a free-form 48-bit BDD as the semantic partition or topology
  authority. Recommended instead serializing the deterministic dyadic decision
  tree as a hash-consed canonical multi-terminal DAG, merging identical
  children and identical host-fact payloads.
- On exact Q8 configuration semantics: preserve host-valid Q8 points and labels
  including isolated rounding-only points, but represent those as symbolic
  terminal sets rather than extra positive-volume convex regions, so existing
  consumers keep mesh-based topology while host localization gets a complete
  authoritative relation. Suggested adding `FP_CONTRACT OFF` and matching
  compiler flags plus differential tests against the binary32 interpreter to
  `tests/run_sg_configuration_semantics_test.sh`.

One review agent flagged an unresolved release-gate issue: plan equivalence
still uses a whole-struct `memcmp`, and wanted explicit semantic comparison
plus a hostile-padding regression test before giving a final verdict.

## Integration map

Measured from `GNUmakefile` object lists, accounting for the root symlinks into
`slipgate/`. Of 251 `slipgate/*.c`: 188 are in the shipped game module, 20 are
generator-only, and 43 reach no module at all.

The 43 unwired ones are not dead so much as unintegrated, and they are where
the project's value is currently stuck: the capability publication layer
(ground, water, external force, static affordance, weapon affordance), the
phase catalog and its owner and publication, the whole hook visibility
feasibility cluster, `sg_bsp_completeness_*`, and the `sg_rune_v2_codec` and
`sg_rune_v2_artifact_loader` remnants of the retired v2 path.

Two consequences worth recording. Verification scaffolding inside this region
costs nothing at runtime today, so removing it buys maintainability rather than
speed. And the plan checkbox for partitioning hook and weapon visibility at
first-hit and silhouette discontinuities is optimistic: the implementation does
axis-aligned interval cuts on quantized coordinates, and the subsystem consults
no occlusion data at all.

## Suggested order of work

1. Wire hook visibility onto `SG_StaticVisibility`. The occlusion service
   exists, is PVS-backed, ships in the game module, and has region-to-surface
   queries, but `sg_hook_visibility_feasibility.c` and
   `sg_hook_visibility_catalog.c` never call it. Filter conservatively — PVS
   cluster, then occluders, then an exact trace at the decision boundary — so
   a filter can never hide a reachable surface. This is the largest scaling
   risk in the design and most of the machinery is already written.
2. Delete the hook visibility verifiers as part of that rewrite rather than
   before it: `SG_HookVisibilityFeasibilityAudit` gates construction in two
   subsystems, so stripping it first means doing the work twice.
3. Delete `sg_bsp_completeness_*` and the `SG_BspCompletenessProve` calls in
   the capability layer, per ART-4 and BSP-5. Construction does not reference
   it, so it is an appendage rather than a dependency.
4. Integrate the capability publication and phase catalog layers into the
   generator, so RUNEs carry movement and weapon fields.
5. `destination_field_caller_migration`. `SG_FieldService` appears only in
   tests; the game still runs on `Field_Flood` reverse Dijkstra over action
   links. This unblocks the strategy caller and is the precondition for
   `legacy_navigation_delete`.
6. Regenerate the orchestrator ledger; its unit states predate everything
   since `0017ab60`.
7. Decide whether to integrate or abandon the two unlanded agent branches.

Naming caution learned the hard way: file names in this tree do not describe
their contents. `sg_hook_visibility_feasibility_proof.c` held the constructor,
not proofs, and was renamed `_construct.c` in `c3dc259a`. Verify symbol by
symbol before deleting anything by filename.
