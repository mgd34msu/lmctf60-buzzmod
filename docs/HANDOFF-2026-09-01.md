# Handoff: Codex fleet stop, 2026-09-01

The Codex agent fleet ran out of usage on 2026-09-01 with a large body of work
uncommitted. This file records what was landed, what was left open, and where
the unlanded material lives so the work can be finished.

## What landed

Commit `a8d9d7a6` on `slipgate` preserves the entire uncommitted working tree:
530 files, 148 added, 186 deleted, 196 modified. It builds clean under
`make -f GNUmakefile` and produces `gamex86_64-lmctf-r1925~0017ab60.so`.

It is one commit rather than several because the change set interlocks: the
toolchain retirement, the compact-model migration, and the build changes all
touch `GNUmakefile` and `Makefile`. Splitting further would produce
intermediate commits that do not build.

Two `clang --analyze` outputs were deliberately left uncommitted and are not
tracked: `sg_rune_compact_mechanisms_build.plist` and
`sg_rune_compact_mechanisms_build_test.plist`.

### Python toolchain retirement

`PROJECT-COMPLETION-PLAN.md` gained the rule that the repository contains no
Python source, tests, build hooks, runtime, or documentation. The commit
implements it: the Python corpus controller, finalizer, bundle, fleet,
analysis, and test programs are gone, along with the duplicate
`runeaccept.c`, `runev2read.c`, and `runev2makecheck.c` parsers.

`tools/runecompactread.c` survives as the single canonical C wire inspector.
`tests/run_c_build_ownership_test.sh` is new and asserts the retired sources
stay deleted and stay out of every build manifest. CI no longer builds a
Python venv or installs `tools/requirements.txt`, and now refuses to package
the offline `-rune-generator.so` as the runtime module.

### Compact model migration

`sg_rune_late_path`, `sg_rune_learning`, and the v2 artifact publication and
semantic units were replaced by `sg_rune_compact_*` equivalents, adding the
compact composer, generation, mechanisms, movement fields, pmove control,
portal snapshot, field service and region hierarchy, response partition,
static materializer, and weapon catalog units with focused tests.

### Documentation

`DEPENDENCY-GRAPH.md` records the offline generator module split: `sv rune`
connects to the compact field builder in an unshipped generator module, while
shipped modules keep only the compact loader/runtime and fail closed on
generation. Three plan checkboxes moved to complete: hook and weapon
visibility partitioning at first-hit and silhouette discontinuities,
static-field caching with a coarse region hierarchy, and probabilistic
weapon-effect integration with exact live pre-fire validation.

## Design work that produced no code

Several 2026-09-01 sessions were read-only evaluation agents that were still in
their grounding phase when usage ran out, so they left no diff. Two produced
conclusions worth keeping:

- On representing the host collision evaluator: rejected compiling the whole
  evaluator into a free-form 48-bit BDD as the semantic partition or topology
  authority. Recommended instead serializing the deterministic dyadic decision
  tree as a hash-consed canonical multi-terminal DAG, merging identical
  children and identical host-fact payloads.
- On exact Q8 configuration semantics: preserve host-valid Q8 points and labels
  including isolated rounding-only points, but represent those as symbolic
  terminal sets rather than extra positive-volume convex regions, so existing
  consumers keep mesh-based topology while host localization gets a complete
  authoritative relation. Suggested adding `FP_CONTRACT OFF` and matching
  compiler flags plus differential tests against the binary32 interpreter to
  `tests/run_sg_configuration_semantics_test.sh`.

One review agent flagged an unresolved release-gate issue: plan equivalence
still uses a whole-struct `memcmp`, and wanted explicit semantic comparison
plus a hostile-padding regression test before giving a final verdict.
